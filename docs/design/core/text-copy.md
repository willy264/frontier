# Text and copy standard: core

Short, concrete, and honest about what exists today.

## Voice

Name the thing, number, and place. Say what is true now. Use `you` for the reader and `we` for the company or project. Pick one spelling convention per project. FRONTIER uses plain international English.

## Humanizer rules

1. No “not X, but Y” contrasts.
2. No dramatic one-line closers or staged openers.
3. No reflex groups of three; use the true number of items.
4. No em dashes in UI copy.
5. No inflated claims such as revolutionary, world-class, or game-changing.
6. Avoid vague attributions without a named source.
7. Do not pad sentences with “in order to” or similar phrases.
8. Never invent numbers, testimonials, logos, partners, or capabilities. Missing facts become TODOs.

## Length limits

Hero headline: 3-8 words. Subheadline: 15-30 words. Eyebrow: 1-3 words. Section heading: 3-8 words. Card title: 2-5 words. Button: 1-3 words, verb first.

## UI formulas

Use verb plus object: `Connect wallet`, `Buy cargo`, `Reveal ambush`. Avoid `Submit`, `Click here`, and `Learn more` without an object. Errors say what happened and the recovery action. Loading over one second says what is loading. Empty states name the space and the first action.

## FRONTIER vocabulary

Use: convoy, port, route, market, ambush, escort, testnet, contract state.

Do not imply: guaranteed profit, AI rivals, mainnet deployment, cross-chain settlement, storms, seasons, or port sub-accounts unless the current evidence proves it.

## Accessible copy

Link text makes sense alone. Alt text describes meaningful content and is empty for decoration. Never communicate a requirement by color only. Keep consumer-facing copy at roughly grade 7-9 readability.
